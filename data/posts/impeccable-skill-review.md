## TL;DR

- 운영 중인 성경일독 사이트 [함온성](https://bible-reading-nu.vercel.app/)에 디자인 스킬 impeccable을 써 봤다. 화면이 확 바뀔 줄 알았는데 기존 UI는 거의 그대로였다.
- 대신 디자인 리뷰(17/40점)에서 "말씀을 고르지 않으면 읽음 기록이 조용히 건너뛰어지는" 버그를 찾아 고쳤다. 44px보다 작은 버튼 11개와 대비가 부족한 버튼도 고쳤다.
- impeccable은 기존 화면을 "다듬는" 것과 "새로 만드는" 것을 나눈다. 나는 다듬는 명령만 골랐다. 그런데 정작 무엇을 골랐는지 모르고 "ㅇㅇ", "ㄱㄱ"만 입력했다.
- 결론: 도구를 알고 써야 원하는 걸 얻는다. 화면만 잘 나오면 된다고 생각하는 사이, 내가 개발자가 아니게 되어 가는 느낌도 들었다.

## impeccable 스킬은 무엇을 하는 도구인가요?

[impeccable](https://impeccable.style)은 AI 에이전트가 뻔한 "AI 티 나는 화면(AI Slop)" 대신 디자이너가 만든 것처럼 완성도 높은 프론트엔드를 만들도록 돕는 오픈소스 스킬 모음이다. Claude Code 같은 에이전트에 설치하면 `/impeccable <명령>` 형태로 쓴다.

명령은 크게 다섯 갈래로 나뉜다.

| 갈래 | 명령 예시 | 하는 일 |
|---|---|---|
| 만들기 | `init`, `shape`, `document` | 제품 맥락(PRODUCT.md)과 디자인 시스템(DESIGN.md)을 정리한다 |
| 평가 | `critique`, `audit` | 화면을 점수 매기고 문제를 찾는다 |
| 다듬기 | `polish`, `harden`, `adapt`, `layout` | 기존 화면의 버그·크기·간격을 고친다 |
| 강화 | `bolder`, `colorize`, `overdrive` | 밋밋한 화면에 색과 개성을 더한다 |
| 반복 | `live`, `generate` | 브라우저에서 여러 안을 띄워 고른다 |

## 운영 중인 서비스에 impeccable을 써 본 상황

함온성은 한 교회 공동체 약 400명이 매일 휴대폰으로 같은 분량의 성경을 읽고, 묵상을 카카오톡 단톡방에 붙여넣어 인증하는 사이트다. 어르신부터 청년까지 함께 쓴다.

사이트의 핵심 흐름은 단순하다. 오늘 분량을 읽고, 마음에 닿은 구절을 고르고, "복사하기"를 눌러 카톡에 붙여넣는다. 버튼을 누르면 구글 시트에 읽음 기록도 남는다.

나는 `init`으로 PRODUCT.md를 만든 뒤 `/impeccable`을 그냥 실행했다. impeccable이 추천한 순서는 `document` → `critique` → `live`였다. 나는 "추천해 준 거 그대로"라고 답했다. 그 뒤로는 거의 "ㅇㅇ", "ㄱㄱ"만 입력했다.

## impeccable은 왜 기존 디자인을 바꾸지 않았나요?

impeccable이 기존 화면을 "다듬기(refinement)"로 다뤘기 때문이다. 다듬기는 기존 정체성과 동작, 문구를 지키고, 화면을 갈아엎는 "다시 만들기(redesign)"는 따로 요청해야 한다.

`document` 명령도 새 디자인을 제안하지 않았다. 코드에 이미 있던 색(청록 요일 띠, 오늘은 노랑, 읽은 날은 민트)과 글꼴(Hahmlet)을 그대로 뽑아 DESIGN.md에 기록했다. 디자인 방향 한 줄도 지금 화면을 보고 "함께 펴는 성경 달력"으로 정리했다.

또 impeccable은 화면의 성격을 모드(mode)로 나눈다. 랜딩 페이지처럼 설득하는 화면(Persuade)에서는 과감하게 바꾸고, 앱처럼 일을 처리하는 화면(Operate)에서는 정확함과 절제를 우선한다. 함온성 홈은 매일 읽고 기록하는 앱 화면이라 Operate였다. 크게 바뀌지 않은 건 도구가 일을 안 해서가 아니라 설계대로 움직였기 때문이다.

## impeccable critique는 어떤 문제를 찾았나요?

`critique`는 홈 화면에 40점 만점에 17점을 줬다. 사용성 휴리스틱(Nielsen heuristics) 10개를 0~4점으로 매긴 결과다. 디자인 리뷰 에이전트와 자동 검사·실측 에이전트를 따로 돌려서 서로의 결과를 보지 못하게 한 뒤 합쳤다.

가장 심각한 문제(P0)는 디자인이 아니라 버그였다.

```javascript
navigator.clipboard.writeText(copyData).then(() => {
  if (!userName) return;
  if (!myMessage) return; // 구절을 안 고르면 여기서 끝난다
  setReadBible({ /* 시트에 읽음 기록 */ });
});
```

구절을 하나도 고르지 않으면 복사는 되지만 읽음 기록은 조용히 건너뛰었다. 화면에는 아무 안내도 없었다. 멤버는 단톡방에 "완료했습니다"를 올리는데, 점검표에는 X로 남는 구조였다.

나머지 지적은 어르신 기준의 크기와 대비였다.

- 44px보다 작은 버튼과 체크박스가 11개였다. 체크박스는 13×13px였다.
- 파란 버튼의 흰 글자 대비가 3.68:1로 웹 접근성 기준(WCAG AA 4.5:1)에 못 미쳤다.
- 달력 칸 안의 분량 글씨("레위기 1-5장")가 8px였다.
- "복사하기"를 누른 뒤 결과가 `console.log`에만 찍혔다.

## harden·adapt·polish로 무엇이 바뀌었나요?

리뷰가 추천한 순서대로 명령을 실행했다. 각 명령이 실제로 고친 것은 아래와 같다.

| 명령 | 고친 것 |
|---|---|
| `harden` | 구절이 없어도 읽음을 기록하고, 결과("✓ 57일차 기록 완료")를 화면에 크게 보여 주도록 했다. 카카오톡 인앱 브라우저용 복사 대체 방법도 넣었다 |
| `layout` | 약 1만 px를 내려가야 나오던 기록 버튼으로 바로 가는 길을 만들었다 |
| `adapt` | 작은 조작 요소 11개를 44px 이상으로, 파란 버튼 대비를 약 5.2:1로, 달력 글씨를 10px로 올렸다 |
| `polish` | 주요 버튼만 강조하고, 화면 이모지를 카톡에 복사되는 글과 맞췄다 |

`harden`을 확인하다가 버그를 하나 더 찾았다. 브라우저가 클립보드 권한을 물으면 `writeText`가 끝나지 않아서 화면이 "기록하는 중"에 멈췄다. 복사에 2초 제한을 걸어 해결했다.

## 원하는 결과를 얻으려면 impeccable을 어떻게 써야 하나요?

명령마다 하는 일을 알고 골라야 한다. 나는 `polish`와 `adapt`를 실행하면서도 그게 정확히 무슨 명령인지 몰랐다. 결과가 나온 뒤에야 "이게 아닌데"라고 느낀 장면이 여러 번 있었다.

- `layout`이 만든 화면 하단 고정 바는 말씀 본문을 가렸다. 결국 내가 요청해서 오른쪽 아래 작은 토스트로 바꿨다.
- 함온성 설정을 큰 스위치로 바꾸자 설정이 메인 버튼보다 더 눈에 띄었다. 기존 사용자가 어르신이라 위치와 체크박스는 원래대로 두고 크기만 줄였다.
- 기도일기 영역은 카톡에 붙여넣는 글과 같은 모양으로 보여야 한다는 걸 내가 직접 말한 뒤에야 맞췄다.

정작 내가 원했던 것은 이런 화면 변화였다. 그런데 이건 `critique`가 아니라 `shape`(만들기 전에 UX 기획)나 `live`(브라우저에서 여러 안 비교)로 시작했어야 할 일이었다. 디자인을 크게 바꾸고 싶었다면 `bolder`나 다시 만들기 흐름을 골랐어야 했다.

## 회고: 화면만 잘 나오면 된다고 생각하는 사이

돌아보면 나는 `init`만 하고 "ㅇㅇ ㄱㄱ"만 입력했다. 내부에서 어떻게 돌아가는지는 관심이 없었다. 화면만 잘 나오고 사용성만 좋으면 된다고 생각했다.

프로젝트가 많아지면서 그렇게 됐다. 그러다 보니 점점 내가 개발자가 아니게 되어 가는 느낌이 들었다. 애초에 impeccable이 디자인을 바꿔 주는 도구라고 오해한 것도 같은 이유다. 알고 쓰는 게 생각보다 훨씬 중요했다.

그래도 수확은 있었다. 함온성의 비즈니스 로직은 결국 "말씀을 읽고, 고르고, 복사한다"가 전부다. 그 핵심 흐름에서 기록이 조용히 실패하던 버그를 디자인 도구가 잡았다.

다음에는 명령을 하나씩 알고 써 볼 생각이다. 해 보고 싶은 기능도 생겼다. 지금은 복사한 글을 카톡에 직접 붙여넣어야 한다. 공유하기 버튼을 만들면 휴대폰의 공유 창(Web Share API)이나 카카오톡 공유 API로 단톡방까지 바로 보낼 수 있을 것 같다.
